## Commands

Spring Boot 4.1 / Java 21 / Maven Wrapper. `JAVA_HOME` must point to a JDK 21. Integration tests use Testcontainers (PostgreSQL); with rootless Podman export these first:

```bash
export DOCKER_HOST=unix:///run/user/$(id -u)/podman/podman.sock
export TESTCONTAINERS_RYUK_DISABLED=true
```

| Task | Command |
|------|---------|
| Compile | `./mvnw compile` |
| All tests + JaCoCo line coverage gate (>= 65%) | `./mvnw verify` |
| One test class / one method | `./mvnw test -Dtest=ReservaIntegracionTest` / `./mvnw test -Dtest=IniciarSesionServiceTest#cuentaBloqueada` |
| Full stack (db, Mailpit, app on :8081) | `cp .env.example .env && podman-compose up --build` |
| App from source against compose db/Mailpit | `podman-compose up -d db mailpit` then `PORT=8082 APP_BASE_URL=http://localhost:8082 ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev` |

Swagger UI: `/swagger-ui.html`. Mailpit UI: http://localhost:8025. Host ports 5432 and 8080 are taken on the main dev machine, so compose publishes Postgres on 5433 and the app on 8081.

## What this is

A service-booking platform ("Plataforma de Reservas de Servicios") for businesses such as clinics, beauty salons, or sports centers. It is an academic project for CodeF@ctory UdeA 2026-2, **advanced team profile**: the deliverable is a robust backend integrated with a database, not a full web app. The course guidelines list the frontend as N/A for this profile. However, `docs/wiki.md` asks for at least one user story delivered end to end (frontend-backend-DB-deployment) in Sprint 1.

Core features, in priority order: users and service providers, schedules (agendas), reservations, resource availability, reservation history, and occupancy reports.

## Architecture

Hexagonal, base package `co.reservas`, main class `co.reservas.infrastructure.ReservasServiciosApplication`. The package tree, dependency rules, use cases, and endpoints are defined in `docs/modelo-datos-y-paquetes.md` §2; do not duplicate them here. Key conventions in the code:

- `domain` is plain Java (records plus small rule classes such as `GeneradorTurnos`, `DetectorReservasAfectadas`, `DetectorConflictosRecursos`). No Spring, JPA, or Jackson imports.
- `application` holds use-case interfaces and records (`port.in`), outbound ports (`port.out`), and `@Service`/`@Transactional` implementations (`service`). Ownership checks (ABAC) live here (`VerificadorPropiedad`). Business errors are `ExcepcionNegocio` with a `CodigoError`; `adapters.in.web.error.CodigosHttp` maps codes to HTTP status.
- `adapters.out.persistence` keeps JPA entities with plain FK ids (no entity graphs). Roles and states are enums resolved to seed-row ids by name through `CatalogoSistema`. Pessimistic locks (`SELECT ... FOR UPDATE`) serialize reservation creation in the order client, service, resources by id.
- Use the `Clock` bean for "now". Integration tests replace it with `RelojAjustable` and replace `NotificacionPort` with `NotificacionesCapturadas` (see `src/test/java/co/reservas/soporte`).
- Schema changes go through new Flyway migrations in `src/main/resources/db/migration`; Hibernate only validates (`ddl-auto=validate`).

Deployment target: the container image on Render (or Railway), with PostgreSQL on Neon (Supabase is an alternative).

Domain vocabulary is Spanish, and code identifiers follow it. The original diagrams contain typos; do not carry them into code (for example `Confing`, `ReservaRepositoyPort`, `infraestructure`, `tblHistorialRersevas`, `fehca`).

## Requirements that shape the code

These come from `docs/lineamientos.md` §3 and `docs/wiki.md`, and they are graded:

- **API**: versioned REST with an OpenAPI/Swagger contract and payload validation. Errors use one uniform body with `errorCode`, `message`, `details`, and `traceId`, and correct HTTP status codes. Logs are structured JSON.
- **Business logic**: rules must go beyond CRUD. Examples: overbooking prevention, availability checks, and state transitions.
- **Security**: RBAC per endpoint, plus simple ABAC where ownership decides access. MFA for admin access. Token expiration, revocation, and rotation. Account lockout after failed logins. CORS restricted. Parameterized queries only. Secrets come from environment variables. Security events are logged without sensitive data.
- **Persistence**: normalized logical and physical models. Indexes must be justified by real queries. At least one stored procedure or trigger, where it fits the architecture. Migrations are versioned.
- **Testing and quality**: unit tests (AAA), integration tests against a real DB or container, and backend acceptance tests. Acceptance criteria are written in Gherkin. SonarCloud/SonarQube quality gate: unit coverage ≥ 65%, technical debt ≤ 2 days, cyclomatic complexity < 50, zero critical vulnerabilities.
- **Delivery**: backend and DB containerized (Docker Compose) and deployed to Render. CI/CD with GitHub Actions starts in Sprint 2. Merges go through PRs with at least 1 approval and a green pipeline.
- **Docs**: architectural decisions are recorded as ADRs (context, alternatives, decision, consequences, owner, date), with at least 3 in Sprint 1. Diagrams and docs must be updated in the same sprint the solution changes.
