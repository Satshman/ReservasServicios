## Detalle por Criterios

### 1. Arquitectura de Solución (PESO: 25%)[cite: 1]
- **Sobresaliente (4):** Justifica de manera completa y consistente todas las decisiones arquitectónicas tomadas durante el proyecto, relacionándolas con el contexto del sistema y sustentándolas mediante criterios técnicos claros de selección, adaptación o ajuste.[cite: 1]
- **Logrado (3):** Justifica la mayoría de las decisiones arquitectónicas tomadas durante el proyecto, relacionándolas con el contexto del sistema y sustentándolas con criterios técnicos pertinentes, aunque algunos son parciales o carecen de profundidad.[cite: 1]
- **En Desarrollo (2):** Justifica únicamente algunas decisiones arquitectónicas. La relación con el contexto del sistema o los criterios técnicos de selección, adaptación o ajuste es limitada, superficial o incompleta.[cite: 1]
- **Insuficiente (1):** No justifica las decisiones arquitectónicas tomadas, o las justificaciones presentadas no guardan relación con el contexto del sistema ni con criterios técnicos de selección, adaptación o ajuste.[cite: 1]

### 2. Cumplimiento funcional orientado a Backend (PESO: 30%)[cite: 1]
- **Sobresaliente (4):** El producto entrega el 100% de las funcionalidades de backend comprometidas para el sprint, completamente implementadas, integradas, probadas y operativas.[cite: 1]
- **Logrado (3):** El producto entrega más del 80% de las funcionalidades de backend comprometidas, implementadas y operativas, aunque algunas presentan limitaciones menores.[cite: 1]
- **En Desarrollo (2):** El producto entrega entre el 40% y el 79% de las funcionalidades de backend comprometidas. Existen funcionalidades incompletas, con limitaciones de integración o de operación.[cite: 1]
- **Insuficiente (1):** El producto entrega menos del 40% de las funcionalidades de backend comprometidas, o las funcionalidades implementadas presentan deficiencias que impiden demostrar su funcionamiento esperado.[cite: 1]

### 3. Calidad Interna (PESO: 25%)[cite: 1]
- **Sobresaliente (4):** El análisis estático de código se encuentra habilitado y evidencia el cumplimiento de los Quality Gates, así:[cite: 1]
  - **Sprint #1:** SOLO cobertura de pruebas unitarias $\ge 65\%$[cite: 1]
  - **Sprint #2 y #3:**[cite: 1]
    1. Cobertura de pruebas unitarias $\ge 65\%$[cite: 1]
    2. Deuda técnica $\le 2$ días[cite: 1]
    3. Complejidad ciclomática $< 50$[cite: 1]
    4. Severidad de hallazgos Minor o superior[cite: 1]
    5. Cero vulnerabilidades críticas[cite: 1]
- **Logrado (3):** El análisis estático de código se encuentra habilitado y se cumple:[cite: 1]
  - **Sprint #1:** Cobertura de pruebas unitarias $\ge 50\%$[cite: 1]
  - **Sprint #2 y #3:** Evidencia el cumplimiento de cuatro (4) de los cinco (5) Quality Gates establecidos.[cite: 1]
- **En Desarrollo (2):** El análisis estático de código se encuentra habilitado y se cumple:[cite: 1]
  - **Sprint #1:** Cobertura de pruebas unitarias $\ge 40\%$[cite: 1]
  - **Sprint #2 y #3:** Evidencia el cumplimiento de tres (3) de los cinco (5) Quality Gates establecidos.[cite: 1]
- **Insuficiente (1):** El análisis estático de código se encuentra habilitado y se cumple:[cite: 1]
  - **Sprint #1:** Cobertura de pruebas unitarias $\ge 30\%$[cite: 1]
  - **Sprint #2 y #3:** Evidencia el cumplimiento de uno (1) o dos (2) de los cinco (5) Quality Gates establecidos.[cite: 1]

### 4. Presentación del Equipo (PESO: 20%)[cite: 1]
- **Sobresaliente (4):** El equipo comunica con claridad, coherencia y propiedad técnica tanto oral como escrita.[cite: 1]
- **Logrado (3):** La comunicación oral y escrita es adecuada con algunas imprecisiones técnicas o de redacción.[cite: 1]
- **En Desarrollo (2):** La comunicación oral y escrita presenta dificultades notorias en claridad o propiedad técnica.[cite: 1]
- **Insuficiente (1):** La comunicación oral y escrita es deficiente; dificulta la comprensión del trabajo realizado.[cite: 1]
